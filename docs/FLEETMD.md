# FleetDM Helm Chart — Implementation Plan

## Overview

Build a first-party Helm chart for FleetDM that replaces the upstream chart's
broken Bitnami subcharts with a clean PXC-backed MySQL integration, optional
Valkey cache, and a full toolchain for testing, documentation, and releasing.

**Key design decisions:**

- The chart does **not** install the PXC operator. It only creates a
  `PerconaXtraDBCluster` CR. The operator is deployed separately (App 1) and
  must be watching the `fleetdm` namespace before this chart is installed.
- Cache (Valkey) is **disabled by default**. Users bring their own
  Redis-compatible instance or enable the bundled Valkey deployment.
- Secrets follow an **existingSecret pattern** throughout. The chart generates
  random credentials by default, but any secret section can be overridden with
  an external secret name (e.g. from 1Password Connect or External Secrets
  Operator). Generated secrets use `helm.sh/resource-policy: keep` to survive
  upgrades.
- Ingress uses **Gateway API `HTTPRoute`** (not the classic `Ingress` kind),
  with an optional cert-manager `Certificate` resource. No gateway-specific
  defaults are set — `parentRefs` name/namespace are values the user must
  provide for their environment.
- **Version management is handled by Renovate/Dependabot**, not manually.
  `appVersion` in `Chart.yaml` tracks the Fleet release tag. Chart version bumps
  independently per semver. These are the only things that change when Fleet
  ships a new release.

## Phase 2 — Templates

### 2.1 `_helpers.tpl`

Beyond the standard name/label helpers, define:

- `fleetdm.mysqlSecretName` — returns `existingSecret` if set, otherwise the
  chart-generated secret name
- `fleetdm.redisSecretName` — same pattern for Redis/Valkey credentials
- `fleetdm.pxcSecretName` — same pattern for PXC operator credentials
- `fleetdm.mysqlAddress` — returns `database.address` if set; if empty and
  `pxc.enabled`, derives `<clusterName>-haproxy.<namespace>:3306`; otherwise
  `fail` with a helpful message
- `fleetdm.redisAddress` — returns `cache.address` if set; if empty and
  `valkey.enabled`, derives from the Valkey service; otherwise `fail`
- `fleetdm.image` — combines `image.repository` and `image.tag`, falling back to
  `.Chart.AppVersion` when tag is empty

### 2.2 `secret.yaml`

Three conditional secrets, each skipped when its corresponding `existingSecret`
is set:

**MySQL secret** — skipped when `database.existingSecret` is set:

```yaml
# helm.sh/resource-policy: keep prevents Helm overwriting the password on upgrade
data:
  <passwordKey>: <randAlphaNum 32 | b64enc>
```

**PXC credentials secret** — skipped when `pxc.existingSecret` is set:

```yaml
# Required keys for the PXC operator — do not rename
data:
  root: <generated>
  xtrabackup: <generated>
  monitor: <generated>
  clustercheck: <generated>
  proxyadmin: <generated>
  pmmserver: <generated>
  operator: <generated>
```

**Redis/Valkey secret** — only rendered when `cache.usePassword: true` and
`cache.existingSecret` is not set:

```yaml
data:
  <passwordKey>: <randAlphaNum 32 | b64enc>
```

### 2.3 `pxc-cluster.yaml`

The `PerconaXtraDBCluster` CR is owned by this Helm release. Gate behind
`pxc.enabled`.

The PXC operator writes status fields back to the CR. Add the following
annotation to avoid ArgoCD treating those writes as drift:

```yaml
annotations:
  argocd.argoproj.io/sync-options: "ServerSideApply=true"
```

The `secretsName` field references the output of `fleetdm.pxcSecretName` —
either the generated secret or the user-supplied `existingSecret`.

### 2.4 `deployment.yaml`

Wire Fleet env vars using the helper functions for address and secret name
resolution:

```yaml
env:
  - name: FLEET_MYSQL_ADDRESS
    value: {{ include "fleetdm.mysqlAddress" . | quote }}
  - name: FLEET_MYSQL_DATABASE
    value: {{ .Values.database.name | quote }}
  - name: FLEET_MYSQL_USERNAME
    value: {{ .Values.database.username | quote }}
  - name: FLEET_MYSQL_PASSWORD
    valueFrom:
      secretKeyRef:
        name: {{ include "fleetdm.mysqlSecretName" . }}
        key: {{ .Values.database.passwordKey }}
  - name: FLEET_REDIS_ADDRESS
    value: {{ include "fleetdm.redisAddress" . | quote }}
  {{- if .Values.cache.usePassword }}
  - name: FLEET_REDIS_PASSWORD
    valueFrom:
      secretKeyRef:
        name: {{ include "fleetdm.redisSecretName" . }}
        key: {{ .Values.cache.passwordKey }}
  {{- end }}
  {{- if .Values.fleet.license.secretName }}
  - name: FLEET_LICENSE_KEY
    valueFrom:
      secretKeyRef:
        name: {{ .Values.fleet.license.secretName }}
        key: {{ .Values.fleet.license.secretKey }}
  {{- end }}
```

Mount a `tmp` emptyDir to satisfy `readOnlyRootFilesystem: true` on the
container security context.

### 2.5 `httproute.yaml`

Renders two documents when both flags are enabled:

1. A `cert-manager.io/v1 Certificate` resource — only when
   `httpRoute.certManager.enabled` is true. References `clusterIssuer` and
   produces a TLS secret named `certManager.certificateName`.

2. A `gateway.networking.k8s.io/v1 HTTPRoute` — always when `httpRoute.enabled`
   is true. `parentRefs` is taken verbatim from values so users can point at any
   gateway without chart changes.

### 2.6 `valkey.yaml`

Renders a `StatefulSet` + headless `Service` when `valkey.enabled: true`. Uses
the `valkey/valkey` image. Persistence is optional — defaults to emptyDir so it
works out of the box without requiring a StorageClass.

When `cache.usePassword: true`, passes the password via env from the
Redis/Valkey secret and starts Valkey with `--requirepass`.

### 2.7 `tests/` — Helm Test Hooks

**test-mysql-connection.yaml** — spins up a `mysql:8.0` pod, runs `SELECT 1`
against the PXC HAProxy service using the Fleet MySQL credentials secret.

**test-valkey-connection.yaml** — rendered only when `valkey.enabled` or
`cache.address` is set. Uses `valkey/valkey` image to run `PING` against the
cache address.

**test-fleet-health.yaml** — uses `curlimages/curl` to hit `/healthz` on the
Fleet service and assert a `200` response. Uses `helm.sh/hook-weight: "5"` to
run after the connection tests.

reason about what ArgoCD will apply — especially for PXC CR changes where a

## Phase 7 — helm-cr (Chart Releaser)

Install: `brew install helm/tap/chart-releaser`

helm-cr packages charts, publishes GitHub Releases, and maintains a `gh-pages`
branch as a Helm repo index. The resulting URL can be used directly in
`helmCharts:` blocks in kustomization.yaml.

### Setup

1. Create a `gh-pages` branch in the chart repo
2. Add a `CR_TOKEN` secret (GitHub PAT with `repo` scope)
3. Configure `cr.yaml` at repo root:

```yaml
owner: your-github-org
git-repo: fleetdm-charts
release-name-template: "{{ .Name }}-{{ .Version }}"
pages-branch: gh-pages
```

**Manual release:**

```bash
cr package charts/fleetdm
cr upload --owner your-org --git-repo fleetdm-charts --token $CR_TOKEN
cr index --owner your-org --git-repo fleetdm-charts --token $CR_TOKEN --push
```

## ArgoCD Integration Notes

Since this chart is deployed via ArgoCD + kustomize with `helmCharts:` blocks:

**Add `ignoreDifferences`** to the FleetDM `Application` to suppress status
field drift written back by the PXC operator:

```yaml
ignoreDifferences:
  - group: pxc.percona.com
    kind: PerconaXtraDBCluster
    jsonPointers:
      - /status
```

**Server-side apply** — the PXC CR template includes
`argocd.argoproj.io/sync-options: "ServerSideApply=true"` so the operator can
own its own fields without conflicting with ArgoCD's three-way merge.

**Secret lifecycle** — generated secrets use `helm.sh/resource-policy: keep`,
which means ArgoCD may show them as out-of-sync after a delete/reinstall. When
using `existingSecret` (i.e. 1Password Connect), the chart skips creating
secrets entirely and this is a non-issue.
